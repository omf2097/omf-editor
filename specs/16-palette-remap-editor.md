# 16 — Palette and remap editor

The Palettes view (`#/palettes`). For a BK document it edits the file's
palettes and their 19 remap tables with tools that make building palettes
practical; for an AF document it configures the palette source and HAR
colours used for preview. Original data for comparison:
<https://katajakasa.fi/projects/openomf/cards/> (generated by pyomftools
`generate_html`; note it numbers remaps 1–19 while this editor and the file
use 0–18).

## 1. How the game uses palettes (from openomf)

Knowing the layout is what makes the tools below meaningful.

- A scene sets its base palette from the BK's **palette 0** and its remap
  tables from palette 0's remaps (`scene.c`). Palettes 1…n are used only by
  specific scenes; the Desert arena swaps indices 0x60–0x9F from palette
  `round` each round (`arena.c`), so for arenas the extra palettes are
  "time of day" variants of that range.
- Index 0 is forced to black and treated as ignored for HAR colours.
- **Arena index layout** (`palette.c`, `pilot.c`):

| Range          | Use                                                        |
| -------------- | ---------------------------------------------------------- |
| 0x00           | black                                                      |
| 0x01–0x2F      | player 1 HAR colours: 3 bands of 16 (primary 0x00–0x0F, secondary 0x10–0x1F, tertiary 0x20–0x2F); 47 entries loaded, index 0 skipped |
| 0x30–0x5F      | player 2 HAR colours, same three bands offset by 48        |
| 0x60–0x9F      | arena-specific colours (64 entries)                        |
| 0xA0–0xFF      | shared UI, fonts, effects; menu colours are written here by the game |

  AF sprites are authored against the player 1 bands (0x00–0x2F); player 2
  draws the same sprites with a palette offset of 48.
- **HAR colour choices** come from `ALTPALS.DAT` palette 0: 16 options × 16
  shades. Choosing option `c` for band `b` of player `p` copies 16 entries
  from `c·16` to `b·16 + p·48`, keeping index 0 (`palette_load_altpal_player_color`).
  A pilot's photo palette (PLAYERS.PIC) can be used instead (colour value 16).
- **Remap tables** are 256-entry lookups, identity by default. Slots openomf
  uses:

| Slot (file 0-based) | Cards site | Use                                                   |
| ------------------- | ---------- | ----------------------------------------------------- |
| 0–3                 | 1–4        | shadow shades, chosen by opacity (`object.c`); 3 also glow |
| 4                   | 5          | background dimming behind menus (`video_draw_remap(…, 4, …)`) |
| 5                   | 6          | dark tint / stasis (`bt` tag, Shadow HAR)             |
| 6–18                | 7–19       | not used by openomf; preserved                        |

  Only palette 0's remaps are used by the game; remaps of palettes 1…n are
  carried in the file but ignored.

The library exposes this as `ARENA_LAYOUT` and `REMAP_SLOT_NOTES` constants
so the UI, diagnostics and tooltips share one source.

```
├ Preview ──────────────────────┤ │ ◯ differs from the compared palette        │
│ [background] [anim ▾] [AF…]   │ │ Selection 0x60–0x6F (16)  ☐ lock to bands  │
│ ┌───────────────────────────┐ │ │ ──────────────────────────────────────────│
│ │ live 320×200 render       │ │ │ idx 0x62  R[22] G[11] B[ 4]  (6-bit)      │

```

Two columns: palette list with usage filters and, under it, the live
preview (left, 400 px), and the editor with Palette / Remaps tabs (right).
The preview stays beside the grid however tall the tools or the remap
editor below the grid get: at 1440×900 grid and preview are in view
together, and at 1024×700 they still sit side by side.

### 2.1 Palette list

Cards for each palette with a small swatch strip, index, and an optional
local label (stored in browser storage, not in the file). Add (duplicate of
the selected; disabled at 8 palettes, openomf `MAX_BK_PALETTES`), delete
(confirm; palette 0 cannot be deleted), reorder by drag with a warning that
the game reads palette 0 as the base. When undo removes the palette being
edited, the editor moves to the last remaining one.

**Usage** toggles mark indices in the grid that are referenced by the
background, by this file's sprites, and optionally by a loaded AF's sprites
(choose a fighter; all are checked against the P1 bands). A counter shows
used/unused indices; **Select unused** picks them for cleanup.

### 2.2 Swatch grid

- 16×16, hovering shows index (hex and decimal), RGB, usage. Region bands
  (P1, P2, arena, UI) drawn as coloured bars beside the row labels
  (0x00–0xF0, at least 0.75rem); toggleable.
- A legend under the grid explains the marks: the row bars with each
  band's name and range (P1 01–2F, P2 30–5F, arena 60–9F, shared A0–FF,
  the description as tooltip); the dot with the usage sources ticked in
  the palette list ("used by the background, this scene's sprites,
  FIGHTR0.AF"); the ring, only while comparing ("differs from the compared
  palette"). The remap editor's mapped grid explains its rings ("maps to 0,
  drawn black") while there are any; the AF grid's dots are "used by this
  fighter's sprites".
- Selection: click, `Shift`+click range, `Ctrl`+click toggle, drag marquee,
  `Ctrl+A`. **Lock to bands** snaps selections to 16-entry bands.
- Keyboard: arrows move the cursor, `Shift`+arrows extend, `Enter` opens the
  colour editor. The grid is one tab stop (the cursor swatch); keyboard
  focus follows the cursor and `Space` selects.
- Marks: dot for "used", ring for "differs from compare palette" (both in
  the legend).

### 2.3 Colour editor

For a single index: R, G, B sliders and fields in **6-bit** (0–63) with the
8-bit and hex equivalents shown, HSL fields, an eyedropper that picks from
the preview canvas, and a native `<input type="color">` for quick picks
(result quantised to 6-bit immediately). For a multi-selection the editor
shows the tools.

### 2.4 Tools (act on the selection; each is one history entry)

| Tool        | Behaviour                                                                                       |
| ----------- | ----------------------------------------------------------------------------------------------- |
| **Ramp**    | Interpolate from the first to the last selected index; endpoints editable in the dialog; RGB or HSL (short or long hue path) interpolation; a grey endpoint takes the other endpoint's hue, so the ramp does not pass through red; optional easing. Preview before Apply. |
| **Shades**  | Generate a 16-shade HAR band from one base colour: dark→light with adjustable black and white points and gamma, matching the shape of the ALTPALS bands. Targets a 16-entry selection or a chosen band. |
| **Adjust**  | Hue shift, saturation, lightness, contrast, gamma, temperature on the selection, live preview, with "Clamp to 6-bit" always on. |
| **Copy / Paste** | Copy the selected entries; paste into a selection of the same size in this or another palette, another BK, or an AF's palette source. Paste reversed. |
| **From ALTPALS** | Load `ALTPALS.DAT`; pick one of the 16 HAR colour options into the selected band (P1 or P2, any of the three). Also pick any of the 11 palettes' ranges. |
| **Swap / Move** | Swap the selected range with the equal-size range starting at the target, or move it so it starts at the target (the entries in between shift). The target must be a whole number that keeps the range inside 0–255. Both offer **Rewrite images**: update every sprite and the background that reference the moved indices, and permute every palette of the file and every remap table the same way, so every picture under every palette and remap stays identical. Without it only the edited palette's colours move and images change colour. |
| **Sort**    | Sort the selection by luminance or hue; always with **Rewrite images** on by default for the same reason. |
| **Fill**    | Set all selected to one colour.                                                                 |
| **Import**  | GIMP `.gpl`, JASC `.pal`, Adobe `.act`, or the palette of an indexed PNG; into the whole palette or starting at the selection. Text formats take plain decimal numbers only; an `.act` with fewer than 256 colours is written with its count trailer. |
| **Export**  | Same formats, plus PNG swatch sheet.                                                            |
| **Compare** | Choose another palette (this file, another BK, or ALTPALS) and show differences with ring marks; **Copy differing entries** in either direction. |

Tool previews are rebuilt from the palette as it is now whenever it changes
(undo, redo, another edit), so **Apply** never brings back undone values.

### 2.5 Remaps tab

```
Remap [ 4 ▾ ]  "background dimming (openomf)"            [Identity] [Copy from ▾] [Invert]
┌ Source (base palette) ───────┐  ┌ Mapped result ────────────────┐
│ 16×16 base colours           │  │ 16×16: entry i shows base[r[i]]│
│ click = select source index  │→ │ click = set target for selected│
└──────────────────────────────┘  └───────────────────────────────┘
entry 0x62 → [ 0x45 ]  swatches: ■ → ■      ☐ show arrows for selection
Tools: Darken · Lighten · Tint · Range map · Shift · Constant · Grayscale · Identity (selection)
```

- Left grid is the base palette (read-only here), right grid shows the
  mapped colours; a selected source range highlights its targets. Set a
  target by clicking in the left grid, typing, or dragging an arrow.
- Entry `null` or out of range cannot occur (u8); mapping to index 0 shows a
  warning marker because 0 renders black.
- **Generation tools** (on the selected source range, with a configurable
  *search range* defaulting to the whole palette, or the same band when
  "lock to bands" is on):

| Tool         | Behaviour                                                                        |
| ------------ | -------------------------------------------------------------------------------- |
| Darken / Lighten by % | For each source index compute the adjusted colour and map to the closest palette entry in the search range (same approach as openomf `palette_resolve_closest` in `lobby.c`). |
| Tint towards colour | Blend each source colour toward a chosen colour by %, then closest-match. |
| Range map    | Map the selected source range linearly onto a target range (e.g. 0x60–0x6F → 0x70–0x7F). |
| Shift        | Target = source + N within the band or clamped.                                  |
| Constant     | Map the whole selection to one index (silhouettes, shadows).                     |
| Grayscale    | Closest grey in the search range by luminance.                                   |
| Identity     | Reset selection to `i → i`.                                                      |
| Copy from    | Another remap slot in this palette, the same slot in another palette or BK.      |

- Tools change the selected entries only, also when the selection is not
  contiguous. Numbers are never wrapped: an index outside 0–255, or a range
  map whose target does not fit, disables **Apply** with a reason.
  Clicking the base grid edits the stored table, never an open tool's
  proposal; the proposal is rebuilt after undo or redo.
- Distance metric for closest-match: weighted RGB (2·ΔR² + 4·ΔG² + 3·ΔB²)
  by default, with a CIE76 option; configurable in the tool dialog.
- The slot dropdown shows the openomf usage note (§1) next to the number so
  authors know which tables matter.

### 2.6 Preview

- Live 320×200 canvas: background (toggle), a chosen animation of this BK,
  and optionally a loaded AF fighter's animation drawn against this palette.
  **P1 / P2** switches the fighter's palette offset (0 or 48) to check both
  bands.
- **Apply remap N** renders everything through the selected remap, which is
  how shadows and tints are previewed.
- **Compare** splits the canvas vertically: left with palette A, right with
  palette B (another palette of the file, with its own stored remap, or an
  ALTPALS palette), draggable divider. A remap tool's proposal applies to
  palette A only.
- Hovering the preview shows the palette index under the cursor and
  highlights it in the grid; clicking selects it (the fastest way to find
  which index to change).

## 3. AF view layout

For a fighter the view is the **palette source** configuration. Left
column: the cards below, then the preview (P1 / P2 and the scene canvas at
1.25×, 400×250) under them; right column: the swatch grid with its legend
(§2.2). Grid and preview are in view together at 1440×900, also with
ALTPALS loaded.

- Source BK picker (recent BKs listed), palette index, remap (default none).
- **HAR colours**: load `ALTPALS.DAT` once (remembered in IndexedDB) and pick
  primary / secondary / tertiary from the 16 options for player 1 and
  player 2, exactly emulating the game's band copy. Without ALTPALS the
  source BK's existing band colours are used. A **Custom** option lets the
  user paste or edit a band with the same tools as §2.4 (Shades, Adjust).
- **Preview as P1 / P2**.
- Usage: which of the 48 band indices this fighter's sprites use, per
  band, and which indices outside the bands. Shipped fighters use the P1
  bands plus the shared range 0xA0–0xF3 (sparks, oil, scrap and
  destruction effects, Electra's lightning), which is normal. Indices in
  0x30–0x5F (player 2 bands) or 0x60–0x9F (changes per arena) are flagged.
- **Use greyscale** fallback.

Nothing here is written to the AF file; the configuration is saved per
fighter in browser storage so it survives reloads.

## 4. Library support (`@omf/formats`)

- `readAltPals(r): Palette[]` / `writeAltPals` — 11 consecutive palettes, no
  header (pyomftools `altpals.py`).
- `ARENA_LAYOUT`, `REMAP_SLOT_NOTES` constants (§1).
- `closestIndex(palette, rgb, range, metric)`, `rampColors`, `shadeBand`,
  `adjustColors`, pure and unit-tested.
- `remapImages(doc, mapping: Uint8Array)` rewrites background and sprite
  indices (decode → map → encode) for the Swap / Move / Sort tools.
- Palette import/export parsers for `.gpl`, JASC `.pal`, `.act`.

## 5. Diagnostics

- Palette 0 index 0 not black (the game overrides it; informational).
- Sprite of a BK referencing indices in the P1/P2 bands (will be recoloured
  by pilots in arenas; informational).
- AF sprite using indices 0x30–0x5F (warning: drawn with player 2's
  colours, or shifted out of range for player 2) or 0x60–0x9F (info:
  colour depends on the arena; one shipped Pyros sprite does this).
  0xA0–0xFF is the shared effects range and is not flagged.
- Remap entry mapping to 0 (informational).
- More than one palette in a non-arena BK (informational; unused by the game).
